# Portal Overview

- Plant, Project, and District choices show all values available to the signed-in user and do not narrow one another. Dashboard access is portfolio-wide for O&M Head, Assignee, and Administration; Site Engineers remain restricted to assigned plants.
- The default Dashboard range is This month. Summary tiles and trends use the selected date range.
- Sidebar Back and Forward arrow buttons use browser history and restore visited portal views without reloading the page on desktop, mobile, and installed PWA layouts. Private O&M data is not cached for offline use.
- Clicking Preventive Maintenance, Washing Compliance, or Open Site Issues opens the matching page in Overview when All plants is selected. When one plant is selected, it opens that plant's matching page. The selected date range is carried to the destination.
- The Inverters tile opens a standalone Inverter Health overlay (not a navigation item). It inherits the current plant, SPV, district, and health filters, uses saved PM unit configuration for inverter totals, and lists open inverter tickets with links into the existing Health register. Only open Inverter tickets with `equipment_running = false` count units as down; Running or unanswered tickets remain open but do not lower plant Health. The plant table and CSV include the latest breakdown remark and a count of additional breakdown tickets.
- The Strings tile opens the matching standalone String Health overlay, with the same searchable per-plant table and searchable column filters. A saved String unit count takes precedence; when none exists, the displayed String total is derived from that plant's Module Cleaning table count and is not written to unit configuration. The Raise Issue picker uses the same count precedence and reads only the selected plant within the caller's issue scope. For both Strings and Inverters, only open tickets explicitly marked as Breakdown (`equipment_running = false`) count their reported units as not working; Running and unanswered tickets remain open but do not lower health.
- The operational trend is a grouped bar chart for the selected plant or plants. Plant, Project, and District filters narrow the trend.
- Washing compliance is the percentage of configured cycles due in each bucket that were confirmed complete on or before their configured due date. Plants without a washing setup are omitted from its denominator.
- PM compliance is the percentage of non-cancelled tasks due in each bucket that were completed on or before their effective planned due date.
- Active site issues are the currently open issue records grouped by their `occurred_at` date; this series is not a historical snapshot of issue status.
- The Module Cleaning portfolio board in Overview defaults to the current month and has a month picker for any past month. Plant, cycle, cleaning-date, and date-specific Entry status filters use that month's plants and dates. Selecting a date shows all visible plants; Entry status can narrow the list to submitted reports or plants with no report. The status filter uses the role-scoped daily washing endpoint and excludes inactive plants from the missing-entry results. Plant and portfolio Module Cleaning calendars have previous/next navigation and Week/Month views; day cells use readable, high-contrast text, show saved table counts and recorded numbers, and display confirmed cycle completion in a separate dark-green chip from the daily cleaning report.
- Overview → BOM keeps each visible plant in a fixed first column. Selecting a plant expands its filtered BOM lines across the remaining columns; details are fetched on demand and cached until filters change, with pagination for large BOMs. The single-plant BOM view and CSV/Excel exports remain available.
- Health pages in both Plants and Overview provide an occurrence-date filter styled like Dashboard: it defaults to the current month, offers quick periods, a month picker for past months, and a toggle for a custom From–To range. Date bounds are sent to the role-scoped issue API, so paging and older months use matching records rather than only filtering the newest page. Clear filters removes the date filter. In the merged plant page, date and import/export/raise controls share the Health heading row; the standalone Views → Health layout is unchanged.
- On the Plants tab, each plant's Info & Health page stacks the saved plant record above its scoped Health register. Portfolio-wide Views → Details shows independently expandable Info and Health panels, both collapsed by default; both are initialized when the page opens, so expanding either panel does not start a new data request. Long Site Engineer and Issue Description cells show one line initially, with a More control only when the content exceeds two lines. In Overview, the Info & Health parent link remains visible while Design/MDL, Liasoning, or BOM is selected; plant names in those portfolio tables do not navigate away to a plant page. On Plants, the Info & Health parent link remains hidden while those plant subpages are active.
- Clicking an issue row opens that plant's Health page; Module Cleaning cards open that plant's cleaning calendar. A saved PM or cleaning record links from its detail dialog to the plant's matching module page.
- Raise issue takes up to four evidence photos. For Inverter issues it asks whether the equipment is Running or in Breakdown; only Breakdown tickets reduce inverter health and require a unit selection (or serial number when no unit configuration exists) and a remark. Each photo is downscaled in the browser before it is sent, and a saved ticket keeps its photos as thumbnails that load only when the ticket is opened; the full-size photo is fetched only when one is clicked. If a photo upload fails the ticket is still saved and the upload can be retried. Opening a ticket shows its photos, and O&M Head or the assignee can add or remove them there.
- In the portfolio Health register, Issue ID appears immediately before Action; Issue Description comes before Maker / Supplier. O&M Head and Assignee open searchable column filters from compact header arrows, including Sub-problem and Maker / Supplier. The compact desktop columns align headers and entries without a horizontal scrollbar. Occurrence dates show the elapsed day count; other roles do not see these controls.
- In Overview → Details, O&M Head and Assignee open searchable value lists from compact column-header arrows; the full filter controls stay hidden until opened.
- **Site Engineer and Security** lists multiple site engineers and security guards per visible plant, with separate 10-digit mobile number fields and a Day/Night duty shift for each person. The Site Code, Site Engineer, and Security Guard column headings include their totals; people are counted per plant, so a person listed at two plants counts twice. Page search matches site code, site engineer, and security names. O&M Head edits contacts in the searchable, site-filtered overlay; O&M Head and scoped Assignees can explicitly move a person to another visible plant. Administration can view the register; contacts are stored with the plant record and remain role-scoped.
- **Requirements** is a separate plant-request register, visible to Site Engineers, Assignees, and the O&M Head. These roles can create tickets with one demand per line; non-empty lines determine the sortable point count. Assignees and the O&M Head can set Critical, Medium, or Low priority and mark a ticket completed or reopen it. Completed tickets leave the Active list but remain in the Completed view. Reads and writes are scoped to the user's assigned plants. Apply migration `047_requirements_tickets.sql` before using this page.
- Compliance percentages use the left axis (0–100%); issue counts use the right axis. Buckets are daily through 31 days, weekly through 366 days, then monthly. Requests are bounded to 10 years.
