# Compact PM, mobile field capture and photo retention

Apply this changes-only update on top of the validated PM release, test fixes and portfolio-only schedule management fix. No new SQL migration is needed: existing site_photos and app_settings columns are reused. Do not run old loader SQL.

- PM matrix compact desktop KPI strip and toolbar; mobile layout uses compact summary, collapsible filters and accessible controls. Other registers benefit from a shared responsive density layer, retaining their existing card views or horizontal table scrolling. The mobile drawer reduces persistent navigation space.
- PM checklist: camera and gallery controls upload real activity UUID/checkpoint/slot links; validate plant, recording role, activity status, date and sequence, checkpoint and slot before and after Storage work. Existing idempotency handles retried submissions. Site issues and module cleaning have explicit native camera controls; module cleaning also accepts PDFs. Pending PM uploads block checklist submission until resolved. There is no durable offline photo queue; a connection is required, and an unsaved selection can be lost when the PWA closes. Physical iOS/Android device testing is required. Supported image formats are JPEG/PNG/WebP; native HEIC files may require camera compatibility settings/conversion.
- Login access > Photo storage: O&M Head sets one automatic retention policy (7–365 days), optionally restricted to a module and plant, and explicitly enables it. The existing app_settings JSON is written and audited. One-off cleanup (1–365 days) uses independent filters and a preview, with confirmation. Scope uses AND when both filters are present. Only old image originals with a separate thumbnail are eligible; metadata, thumbnails, PDF reports and operational records remain. Deletion is irreversible. The DB row is marked original_purged_at after successful Storage deletion; Storage and Postgres are not one atomic transaction, so retry/monitor failures. A process-local lock prevents concurrent sweeps in the same worker, not across replicas. Keep one retention worker. Existing deployment opt-in PHOTO_RETENTION_DAILY_JOB=1 is honored until overridden by explicit portal policy.
- Production checks hourly and runs once per UTC day per awake process, retrying failures on the next tick. A restart may cause another idempotent sweep. Render Free sleeping means no guaranteed wall-clock execution; the next wake checks eligibility. Use a continuously running single worker for a reliable daily schedule. Automatic deletion is off until explicitly enabled (unless legacy deployment opt-in is already set). Check logs and storage usage; manual sweep remains available.
